- 기준 코드: `50b126f754b4d8f1a9c80f75673d98c1c37e1509`의 `분석 앱/app.R`.
- 작업일: 2026-11-18.
- 승인 범위: 기존 기능 보존형 분리, 설정·인증·문맥 로딩 분리, 오류 처리, 유효한 대응 쌍 기준의 통계 표시, R 환경 준비, 합성 자료·대체 모형 검증, README 개편과 대체 코드 정리.
- 최상위 프로젝트 폴더명은 유지했다. 다른 프로젝트·상위 `PROJECT_GOALS.md`·`reference/`는 수정하지 않았다.
- 업무 설명은 상위 작업 폴더의 `reference/records/project-domestic-clothing-industry-analysis.md`, 회사 경력 기록 및 `reference/README.md`의 공개 범위를 따랐다. 고객 식별 명칭·원본 재무자료·내부 화면을 README에 옮기지 않았다.

사용자 확인 사항:

1. `context.final.RData`는 모형 학습 정보를 저장한 파일이며 현재 보유하고 있지 않다. 실제 파일의 모든 객체와 학습 절차는 확인하지 못했다.
2. 2016·2022년은 확보 표본이 적어 분석에서 제외했지만, 존재하는 정보를 제공하기 위해 조회·다운로드에서는 제외하지 않았던 것으로 기억한다.
3. AI 입력 단위는 정확히 기억하지 못하므로 코드의 `0.01` 변환과 `%` 표시를 유지한다.

## 파일과 실행 경로

`분석 앱/app.R`의 구현을 `analysis_app/app.R`, `ui.R`, `application.R`, `bootstrap.R` 및 아래 기능 폴더로 대체했다.

| 폴더 | 책임 |
| --- | --- |
| `data` | 문맥 파일을 독립 환경에 읽고 객체·열·기업 ID·기업/연도 조합·변수 수 검사 |
| `authentication` | 외부 인증 파일 로딩, 인증된 사용자 확인, 선택적 로컬 폰트 설정 |
| `extraction` | 기존 검색·연도 보유 조건, 기업/재무 연결, 결측 현황·산업분류 조회 |
| `overview` | 반복 열의 빈도 집계, 클릭한 항목의 기업 선택 |
| `finance` | 분석 연도, 이상치 처리, 분포와 브러시 선택 |
| `hypothesis` | 유효한 대응 쌍, 기술통계, Wilcoxon 검정 |
| `prediction` | 모형 선택, 입력 변환, 확률·학습 데이터 성능·중요도 |
| `downloads` | 선택 기업 원본의 Excel 생성 |

이전 실행 파일은 검증 후 제거했고 호환용 파일은 남기지 않았다. 기존 JPG 8개와 배포 메타데이터는 `analysis_app/` 아래로 이동했으며 총 9개 파일의 이동 전후 SHA-256이 일치했다. 앱에서 참조하지 않는다는 이유로 삭제하지 않았다. `image/app_vis_1.png`는 그대로 보존하고 README의 화면 삽입만 제거했다. 기존 배포 기록은 재배포 또는 현재 배포 성공의 근거가 아니다.

## 기능 보존과 변경 영향

| 항목 | 처리 기준 |
| --- | --- |
| 검색 | 공백 제거, 소문자 `or` 분리, 정규식 부분 일치를 유지. 정규식을 일반 문자열 검색으로 바꾸지 않음 |
| 종업원 수 | 결측값 포함을 선택하면 종업원 수 범위 제한도 적용하지 않는 기존 동작 유지 |
| 연도 And/Or | 기업이 해당 연도를 보유하는지로 기업을 선택하며, 선택 기업의 재무 자료를 그 연도 행으로만 축소하지 않음 |
| 연도 정책 | 조회 선택지는 전체 보유 연도, 분석 선택지는 그중 2016·2022년 제외. 원래 `finance.date` 값은 파일 부재로 재현하지 못했으며 사용자 설명에 따라 명시화 |
| 개요 집계 | 주요사업·상품·매출처의 반복 열은 건수로 집계. 선택 기업은 중복 없이 반환 |
| 이상치 | 추출 화면의 재무 요약은 전체 자료의 수염 경계 안쪽만 사용. 재무 탭은 연도별 경계를 계산하고 경계값을 포함 |
| 가설검정 | 기업 ID로 짝을 맞추고 첫 연도−둘째 연도 방향과 대립가설 유지. 그림 표시 범위와 검정 대상은 구분 |
| 다운로드 | 세 버튼 모두 선택 기업의 원본 모든 연도 제공. 기본 추출만 ID를 포함하고 개요·재무 다운로드는 ID 제외 |
| 예측 | 22개 순서·`0.01` 변환·다섯 모형 선택 순서·이전/이후 출력 유지. 입력은 예측 버튼 시점에 저장되고 모형 변경은 현재 입력에 적용 |
| 성능 표시 | 학습 데이터에 대한 혼동행렬 기능 유지. 별도 평가 성능으로 해석되지 않도록 설명 추가 |
| 화면 | 원래 다섯 탭과 입력 식별자 유지. 로그인 기능과 선택적 관리자 속성도 유지 |

명시적으로 달라지는 부분:

- 결측·비유한 값이 있는 대응 쌍은 요약표와 검정에서 함께 제외하고 제외 수를 표시한다. 이러한 자료에서는 표시 표본 수와 기술통계가 달라질 수 있다.
- 같은 연도, 중복 기업/연도, 유효한 쌍 없음, 모든 차이가 0인 경우에는 검정을 강행하지 않고 안내한다.
- 밀도 그래프에 필요한 표본이 부족한 경우 안내하며, 여러 연도를 그릴 때 유효 값이 두 개 이상인 연도만 그린다.
- 다운로드 버튼은 자료의 실제 행 수로 활성화한다. 그림 렌더링 중 공유 선택 상태를 수정하지 않고, 개요 항목·조회 자료가 바뀌면 클릭 선택을 초기화한다.
- 자료·인증 경로는 외부 설정으로 받는다. 추가 저장 객체를 전역 환경이나 UI 환경에 무제한 노출하지 않고 실제 의존 객체만 사용한다.
- Google Fonts의 시작 시 자동 다운로드를 제거했다. 로컬 폰트를 지정할 수 있으며 지정하지 않으면 실행 환경 기본 폰트를 사용하므로 글꼴 외형은 달라질 수 있다.
- 모형 파일·인증 파일을 저장하거나 새로운 업무 모형을 학습하는 기능을 추가하지 않았다.

## 검증 환경과 부작용

공식 R 4.6.2 Windows 설치 파일을 체크섬과 대조한 뒤 설치 프로그램을 실행하지 않고 `.runtime/R/`에 풀었다. 패키지는 `.runtime/library/`, 브라우저 검증 도구는 `.runtime/browser/`에 준비했다. 전역 R 설치·파일 연결·사용자 패키지 설정은 변경하지 않았다.

패키지 설치 단계에서는 공식 저장소에서 파일을 다운로드했다. 앱과 테스트의 입력은 합성 기업·연도·재무자료 및 대체 모형이며 업무 원자료를 외부 서비스에 보내지 않았다. 브라우저 서버는 `127.0.0.1`에만 바인딩하고 일회성 인증값은 메모리·자식 프로세스 환경에서만 사용하며 출력·문서·파일에 저장하지 않는다. 검증 종료 시 서버와 브라우저를 닫는다.

테스트의 Excel·이미지·결과 로그는 `tests/output/` 또는 임시 폴더에 생성된다. `tests/fixtures/extraction-baseline.rds`는 기존 추출 로직으로 만든 합성 기준 결과이며 업무 데이터나 원래 모형을 포함하지 않는다.

## 수행 검증

최종 결과: **19개 테스트 사례, 120개 검증 항목 통과**, 실패·오류·경고 없음. 실제 Chrome에서 수행한 브라우저 검사 10개도 통과했고 JavaScript 오류와 최종 화면 오류는 없었다. `dependencies-tested.csv`에 실행 환경의 패키지 버전을 기록했다.

R 파일 25개의 구문 검사를 통과했다. 브라우저에서 받은 Excel 세 파일을 다시 읽어 원본의 2016·2022년 정보가 유지되고 기본 추출 파일만 ID 열을 포함하는 것을 확인했다. 조회·재무·예측 화면 이미지도 확인했으며 검증 서버는 종료했다.

기존 `app.R`을 파싱해 추출 반응식의 계산 부분만 독립 환경에서 실행했다. 이 과정에서 앱 시작, 원래 인증 설정, 폰트 다운로드, RData 로드는 실행하지 않았다. 다음 합성 조건 10개에서 기업 ID와 기업·연도 결과를 기록하고 새 구현과 비교한다.

- 기본 조회, 여러 지역, 종업원 수 범위, 개인/법인
- 연도 And, 연도 Or, 표본이 적었던 연도 조회
- 복수 검색어·공백 처리, 빈 결과, 복합 조건

추가 검증은 문맥 계약·원본 보존·반복 항목 집계·서로 다른 이상치 기준·유효한 대응 쌍·다운로드 범위·22개 입력 변환·인증 차단·세션 분리·버튼 시점 반응을 포함한다. 실제 caret 패키지로 별도의 작은 합성 GLM을 학습해 기본 예측·혼동행렬·중요도 호출 계약도 확인한다. 이 합성 모형은 원래 모형을 대체하는 업무 산출물로 저장하지 않는다.

브라우저 검증은 로그인 실패·성공, 다섯 탭, 기업 조회, 개요 그래프 클릭, 재무 브러시, 세 종류의 Excel 다운로드, 두 연도 검정, 예측 입력과 모형 변경, 학습 성능 표기와 중요도 그래프를 대상으로 한다. 예측 화면의 확률과 중요도는 대체 모형의 고정된 합성 결과다.

프로젝트 루트에서 테스트를 재실행할 수 있다.

```powershell
$env:R_LIBS_USER = (Resolve-Path ".runtime/library").Path
$env:LC_ALL = "English_United States.utf8"
& .\.runtime\R\app\bin\Rscript.exe --vanilla tests/run-tests.R
node tests/browser-check.cjs
```

브라우저 검증은 Windows의 Chrome과 `.runtime/browser`에 설치한 `playwright-core`를 사용한다. 일반 업무 실행 경로에서 테스트 자료·대체 모형을 자동으로 불러오지 않는다.

## 한계

- 실제 `context.final.RData`, 원본 기업·재무자료와 원래 학습 모형을 확보하지 못했다. 실제 객체 구조·모형 입력 단위·과거 예측값·업무 분석 수치의 일치는 검증하지 못했다.
- 합성 자료의 기존 로직 비교와 UI 검증은 모든 실제 데이터 상태에 대한 동등성을 입증하지 않는다.
- 기존 shinyapps.io 서비스의 현재 상태·배포·운영 계정은 확인하거나 변경하지 않았다. 로컬 검증과 공개 서비스 검증을 구분한다.
- 현 단계의 완료 범위는 승인된 앱 코드 정제와 합성 자료 검증이다. 실제 자료가 확보되면 별도 범위로 재검증한다.
